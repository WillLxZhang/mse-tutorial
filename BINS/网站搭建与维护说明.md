# MSE_Tutorial 网站搭建与维护说明

## 1. 现在这个网站会一直挂着吗

不会。

现在打开的 `http://127.0.0.1:8001/` 是本机预览地址。它只在这台电脑开着预览服务时有效。

只要满足这几个条件，它就能访问：

- 这台电脑开着。
- 预览服务进程还在运行。
- 端口没有被关闭。
- 浏览器访问的是这台电脑自己的 `127.0.0.1`。

如果电脑关机、重启、进程停止，网站就不再挂着。

这个地址适合本地编辑和预览，不适合正式发布。

## 2. 其他设备能不能访问 `http://127.0.0.1:8001/`

不能。

`127.0.0.1` 的意思是“当前设备自己”。每台电脑、手机都有自己的 `127.0.0.1`。

所以：

- 你在这台电脑访问 `http://127.0.0.1:8001/`，访问的是这台电脑上的预览服务。
- 其他电脑访问 `http://127.0.0.1:8001/`，访问的是其他电脑自己，不会访问到你的电脑。
- 手机访问 `http://127.0.0.1:8001/`，访问的是手机自己，也打不开你的本机网站。

如果要让其他设备访问，有两种方式。

### 方式 A：局域网临时访问

适合在同一个 Wi-Fi 下给别人临时看。

做法：

1. 查这台电脑的局域网 IP。

   ```powershell
   ipconfig
   ```

2. 找到类似 `192.168.x.x` 的 IPv4 地址。

3. 启动预览服务时监听局域网地址，例如：

   ```powershell
   D:\Science\bins\buf\mse_tutorial_mkdocs_venv\Scripts\mkdocs.exe serve -f D:\Learning\学生工作\MSE_Tutorial\mkdocs.yml -a 0.0.0.0:8001
   ```

4. 同一 Wi-Fi 下的其他设备访问：

   ```text
   http://你的局域网IP:8001/
   ```

例如：

```text
http://192.168.1.23:8001/
```

注意：

- 这仍然是临时预览。
- 电脑关机后失效。
- 换网络后 IP 可能变化。
- 防火墙可能拦截。

### 方式 B：正式发布到公网

适合给所有人长期访问。

推荐方式：

- GitHub Pages
- Cloudflare Pages
- Vercel
- Netlify

当前项目最适合先用 GitHub Pages。

发布后地址会类似：

```text
https://你的用户名.github.io/仓库名/
```

这类地址才能让其他设备长期访问。

## 3. 能不能改成 `mse_tutorial.com`

可以实现，但 `mse_tutorial.com` 这个域名形式不建议用，也很可能不能作为标准域名注册。

原因：域名通常使用字母、数字和短横线 `-`，不使用下划线 `_`。

建议用这些形式：

```text
mse-tutorial.com
msetutorial.com
mse-tutorial.org
tutorial.example.com
```

如果要绑定自定义域名，大致流程是：

1. 购买域名。
2. 把网站发布到 GitHub Pages 或 Cloudflare Pages。
3. 在域名服务商那里配置 DNS。
4. 在 GitHub Pages 或托管平台里填写自定义域名。
5. 开启 HTTPS。

如果用 GitHub Pages，仓库里通常会有一个 `CNAME` 文件，内容是你的域名。

例如：

```text
mse-tutorial.com
```

现在先不用改。等网站内容确定、仓库建好、发布流程跑通后，再绑定域名更稳。

## 5. 每个文件改什么

### `mkdocs.yml`

用途：网站配置。

改这些内容：

- 网站名称。
- 网站简介。
- 作者。
- GitHub 仓库链接。
- 导航栏。
- 主题配置。

常见修改位置：

```yaml
site_name: "[待填写：网站名称]"
site_description: "[待填写：一句话介绍网站]"
site_author: "[待填写：维护团队或个人]"
```

如果要新增页面，也要在 `nav` 里加入口。

例：

```yaml
nav:
  - 首页: index.md
  - 关于: about.md
  - 投稿: contribute.md
  - 栏目名称:
      - 栏目首页: section-name/index.md
      - 文章标题: section-name/article-name.md
```

### `docs/index.md`

用途：首页。

改这里：

- 网站标题。
- 网站简介。
- 如何使用。
- 内容目录。
- 投稿方式。
- 更新记录。

首页是别人打开网站第一个看到的页面。

### `docs/about.md`

用途：关于页面。

改这里：

- 项目背景。
- 维护团队。
- 内容原则。
- 版权和授权说明。

### `docs/contribute.md`

用途：投稿页面。

改这里：

- 投稿方式。
- 投稿格式。
- 审稿流程。
- 发布流程。
- 隐私确认要求。

### `docs/page-templates/article.md`

用途：经验文章模板。

新增经验文章时，复制这个文件，再改成正式文章。

不要直接在模板里写正式文章。

### `docs/page-templates/section.md`

用途：栏目页模板。

新增栏目时，复制这个文件，作为栏目首页。

### `docs/page-templates/publish-checklist.md`

用途：发布检查清单。

每次发布前照着检查。

可以按团队实际流程继续补充。

### `docs/assets/images/`

用途：放图片。

建议：

- 图片文件名用英文、数字和短横线。
- 不要用空格。
- 不要直接上传未打码截图。

例：

```text
docs/assets/images/example-offer-masked.png
```

Markdown 引用方式：

```markdown
![图片说明](assets/images/example-offer-masked.png)
```

如果文章在子目录里，路径要按相对位置调整。

## 6. 如何新增一个栏目

假设要新增一个栏目，栏目名先用占位名 `section-a`。

### 第一步：建目录

在 `docs/` 下新建目录：

```text
docs/section-a/
```

### 第二步：复制栏目模板

把：

```text
docs/page-templates/section.md
```

复制为：

```text
docs/section-a/index.md
```

### 第三步：修改栏目内容

打开：

```text
docs/section-a/index.md
```

把 `[待填写]` 改成正式内容。

### 第四步：加入导航

打开：

```text
mkdocs.yml
```

在 `nav` 里加入：

```yaml
  - [待填写：栏目名]:
      - 栏目首页: section-a/index.md
```

### 第五步：预览

打开本地预览地址检查。

## 7. 如何新增一篇文章

假设文章文件名叫 `example-article.md`。

### 第一步：复制文章模板

把：

```text
docs/page-templates/article.md
```

复制到目标栏目目录，例如：

```text
docs/section-a/example-article.md
```

### 第二步：修改文章内容

打开：

```text
docs/section-a/example-article.md
```

把 `[待填写]` 替换成正式内容。

### 第三步：加入导航

打开：

```text
mkdocs.yml
```

在对应栏目下加一行：

```yaml
  - [待填写：栏目名]:
      - 栏目首页: section-a/index.md
      - [待填写：文章标题]: section-a/example-article.md
```

### 第四步：更新栏目文章列表

打开：

```text
docs/section-a/index.md
```

把文章加到表格里。

例：

```markdown
| 标题 | 作者/称谓 | 时间 | 关键词 |
| --- | --- | --- | --- |
| [文章标题](example-article.md) | [待填写] | [待填写] | [待填写] |
```

### 第五步：预览和检查

检查：

- 页面能打开。
- 导航能点击。
- 链接没有断。
- 图片能显示。
- 没有隐私信息。

## 9. 如何检查能不能正式构建

运行：

```powershell
D:\Science\bins\buf\mse_tutorial_mkdocs_venv\Scripts\mkdocs.exe build --strict -f D:\Learning\学生工作\MSE_Tutorial\mkdocs.yml -d D:\Science\bins\buf\mse_tutorial_site_build
```

```text

```

说明构建成功。

如果报错，先看：

- `mkdocs.yml` 缩进是否正确。
- `nav` 里写的文件是否存在。
- Markdown 链接路径是否正确。
- 图片路径是否正确。

## 10. 如何正式发布

推荐用 GitHub Pages。

基本流程：

1. 新建 GitHub 仓库。
2. 把当前项目提交到仓库。
3. 安装依赖。
4. 构建网站。
5. 发布到 GitHub Pages。

手动发布命令通常是：

```powershell
D:\Science\bins\buf\mse_tutorial_mkdocs_venv\Scripts\mkdocs.exe gh-deploy -f D:\Learning\学生工作\MSE_Tutorial\mkdocs.yml
```

前提：

- 已安装 Git。
- 项目已经是 Git 仓库。
- 已经关联 GitHub 远程仓库。
- 当前账号有推送权限。

发布成功后，别人访问的是 GitHub Pages 地址，不是 `127.0.0.1`。

## 11. 日常维护流程

建议每次更新按这个顺序：

1. 收到投稿。
2. 确认作者授权。
3. 检查隐私信息。
4. 复制文章模板。
5. 填写文章内容。
6. 更新栏目页文章列表。
7. 更新 `mkdocs.yml` 导航。
8. 本地预览。
9. 运行构建检查。
10. 提交到 GitHub。
11. 发布或等待自动发布。

## 12. 隐私和权限检查

发布前重点检查：

- 学号。
- 身份证号。
- 手机号。
- 微信号。
- 邮箱。
- 成绩截图。
- offer 截图。
- 简历。
- 推荐信。
- 聊天记录。
- 他人姓名和联系方式。

默认不要公开这些内容。

确实要公开时，必须确认作者同意。
