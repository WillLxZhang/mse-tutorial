## 一、什么是 AI 与 Vibe Coding？



我们可以把 AI 先简单地理解为模型。

大家想必都接触过豆包 / DeepSeek / Chatgpt 等 AI 模型。你会发现：在网页端，你可以和这些模型进行对话，问它问题，它都能给你回答。为什么呢？

我们可以把 AI 简单地理解为一个函数：

$$
f(x) = a_0 + a_1 x + a_2 x^2 + \cdots
$$

梁文峰叔叔通过来自人类的互联网数据去训练，让这个函数获得一组正确的 a ，这样他就知道，如何通过我输入的任何 x 输出我想要的 f(x)。

这里的 x 就是 prompt ，又名提示词，可以理解为你让 AI 干的事情。

这些模型就是**LLM（大语言模型）**，它们就是 GPT、Claude、DeepSeek 等背后的技术——通过海量数据训练出来的，具有语言理解与生成能力模型。本质来讲，这是对人类经验的重构，也就解释了前面的问题：一个汇集了所有人类知识的百科全书，当然能回答你的任何问题。

但是网页端的 AI 似乎只能和你对话，并且生成一些图片和文件，如果它能够接管我的电脑呢？

向你介绍 Agent：

简单理解，Agent 是一个能够围绕目标进行多步骤决策、调用工具并利用反馈继续执行任务的系统。

例如用户要求：「帮我把Python程序作业写掉」

Agent 可能执行如下过程：

1. 查看项目结构
2. 阅读项目依赖与现有代码。
3. 设计接口。
4. 创建或修改 Python 文件。
5. 执行单元测试。
6. 读取报错。
7. 修复错误。
8. 再次执行测试。
9. 汇报结果。

前述的模型是其决策的核心，Agent 则体现为完整的任务执行机制。我们日常所说的 codex / claude 就是这样的 Agent 平台，它从网页端的框架里跳了出来，能操作你电脑上的所有文件。

OK，我们现在可以得出一个很棒的结论：所有能够被信息化的东西，都能被 AI 所操作、呈现甚至取代，也就是凡是能网上找到的内容，基本它都能干。

那我们能够利用这个能力做什么呢？

向你介绍 Vibe Coding。

一切信息化的内容都可以由代码呈现，我们学的C语言可以用来编写单片机，Python 可以用来控制机器人，Java 可以用来承载网页。

这样来讲，会编写代码，基本就等于开了创造模式，你可以在虚拟世界创造任何你想要的东西。

但我不会写代码，怎么办？

没关系，现在是 Vibe Coding 的时代。

**Vibe Coding 是一种以自然语言驱动的软件开发方式。** 我们不再需要手敲每一行代码，直接用给 AI 的自然语言描述我们的需求，AI 会替我们把活干掉。

截止 2026 年年底这个时间点，大模型已经能解决大部分本科学生遇到的任何工程问题。

介绍环节结束，我们来学习如何使用 AI。

## 二、几个 AI 应用实例

首先，这里有四个机械学院常见且常用实际简单例子供大家参考：课程报告写作、基础的嵌入式控制STM32，常见的视觉模型YOLO，机器人仿真中通用性较强的Mujoco。

看完这些后，大家或许会对怎么使用 AI 有一个新的认知。


### 实例一：课程报告写作

课程报告也是机械学院同学经常遇到的任务。假设老师要求我们写一篇 **以人形机器人为主题的综述报告，需要梳理主要研究方向、比较代表性工作，并列出参考文献**。

#### 1. 在 Vibe Coding 时代之前

传统写作大概需要经历这样的流程：

1. **先明确题目和要求。** 阅读课程要求，确定报告篇幅和讨论范围。人形机器人涉及机械设计、运动控制、感知等方向，直接从整个领域入手，很容易写成什么都讲一点的概念介绍。
2. **检索论文和资料。** 在学术搜索平台、期刊网站和官方项目页面里查找相关工作，逐篇记录作者、发表时间和研究内容。
3. **阅读并整理文献。** 看摘要、方法和实验，搞清楚每篇文章解决了什么问题、采用了什么方法，以及结果适用于什么条件。
4. **搭建报告结构。** 按研究问题或技术路线组织材料，制作比较表，再写出自己的归纳与分析。
5. **处理引用和排版。** 把正文引用与参考文献逐项对应，检查图片来源、术语、格式和重复内容。

经常是论文下载了一堆，浏览器开了几十个标签页，真正开始写的时候，还是不知道这些材料该怎么串起来。

#### 2. 在 Vibe Coding 时代

我们可以把课程要求、已有材料和自己感兴趣的方向交给 Agent，让它帮助完成检索、整理和文档处理。

**Prompt 示例：**

> 我需要完成一篇以“人形机器人”为主题的课程综述，课程要求和已有资料放在当前文件夹里。
>
> 请先阅读这些材料，整理篇幅、格式和评分要求，并和我确定一个适合课程报告的讨论范围，再给出提纲。
>
> 围绕确定的主题，检索原始论文和官方项目资料，整理一份文献表，列出标题、作者、年份、原文链接、研究问题和主要结论。请实际打开来源核对，无法访问或确认的信息标出来，引用和实验数据都要能追溯到原文。
>
> 以这份文献表为依据，帮助我比较不同技术路线，形成报告初稿。区分论文作者的结论与我们自己的分析，检查正文引用和参考文献是否一一对应。
>
> 最后按课程要求整理成可编辑文档，并告诉我哪些论文和关键结论需要重点复核。

在具备联网检索、文件读取和文档编辑能力的情况下，Agent 可以帮助我们完成：

**阅读课程要求 → 整理文献 → 比较研究路线 → 起草正文 → 检查引用 → 调整格式。**

如果我们读到某个方法不理解，还可以继续问它：「这篇论文里的控制方法解决了什么问题？请结合文中的公式和实验，解释它与前一篇工作的区别，并给出对应页码或章节。」

我们主要需要负责确定讨论重点、读懂关键文献，并判断比较是否公平。尤其要核对论文是否真实存在、结论有没有被夸大，以及不同实验条件下的数据能不能直接比较。

这样，写综述的精力可以更多地放在理解问题、组织观点和形成自己的判断上。

### 实例二：STM32——从点亮 LED 到控制电机

对于机械学院的同学来说，STM32 应该不是什么陌生的东西。从单片机课程设计到各种机器人、智能车项目，我们或多或少都和它打过交道。

假设我们今天需要使用一块 **STM32F103 开发板，实现 PWM 控制舵机，并通过串口接收控制指令**。

#### 1. 在 Vibe Coding 时代之前

传统开发大概需要经历这样的流程：

1. **先去找教程。** 打开 CSDN 或 B 站，搜索「STM32F103 PWM 控制舵机保姆级教程」，从一堆使用不同开发板、不同 HAL 库版本的教程里找到适合自己的。

2. **下载并配置开发环境。** 安装 STM32CubeMX、Keil MDK 或 STM32CubeIDE，配置编译器、驱动和调试器。

3. **研究外设配置。** 在 CubeMX 里面配置系统时钟、GPIO、TIM 定时器、PWM 通道和 UART 串口。有时候还得翻一翻芯片的数据手册，确认引脚复用关系。

4. **编写程序。** 找到对应的 HAL 库函数，配置 PWM 频率、占空比，以及串口接收中断，再编写舵机角度控制逻辑。

5. **编译、烧录、调试。** 喜提 `undefined reference`、时钟配置错误、串口收不到数据，或者舵机一动不动。

6. **继续搜索报错。** 把错误信息复制到 CSDN、GitHub Issues 或搜索引擎里，再找到一篇不一定适用于当前开发环境的教程。


折腾一下午，舵机终于转了。至于为什么能转，可能还没完全搞明白。

#### 2. 在 Vibe Coding 时代

我们可以直接打开 Codex 或 Claude Code，告诉 Agent 自己使用的开发板、硬件连接方式和具体需求。

**Prompt 示例：**

> 我正在使用 STM32F103 开发板，希望通过 PWM 控制一个普通舵机，并通过串口发送目标角度。
>
> 请参考 STM32 官方 HAL 库和相关开发文档，帮我建立完整的嵌入式工程。
>
> 首先确认芯片型号、引脚连接、时钟配置和开发工具链，再实现定时器 PWM 输出、串口通信及舵机角度控制。
>
> 请尽可能自动完成代码编写、编译检查和错误修复，最后向我介绍如何烧录、接线和验证功能。

如果 Agent 能够使用本地终端、读取工程文件，并调用相应的编译工具，它就能帮助完成相当一部分重复劳动。

我们主要需要负责提供正确的硬件信息、检查接线与供电，并在真实开发板上验证程序是否正常。

**值得注意的是：编译成功不等于硬件一定能正常工作。** Agent 没有合理的配置情况下，无法仅靠阅读代码就确认电机接线、电源电压和真实运动是否正确。

但它确实可以让我们少花很多时间寻找外设配置教程，把精力更多地放在实际的控制问题上。


### 实例三：YOLOv8——从 GitHub 项目到自己的视觉检测程序

在机器人工程和机械自动化相关项目中，我们经常需要识别物体、检测零件位置，或者使用摄像头获取环境信息。

假设我们希望搭建一个 **基于 YOLOv8 的视觉目标检测程序**，能够识别摄像头画面中的物体，并显示检测框。

这里是一个项目仓库：[https://github.com/ultralytics/ultralytics](https://github.com/ultralytics/ultralytics)。我们该如何实现呢？

### 1. 在 Vibe Coding 时代之前

1. **寻找项目和教程。** 打开 CSDN 搜索「YOLOv8 环境搭建教程」，再打开 GitHub 找到 Ultralytics 官方仓库，阅读 README，研究怎么安装和运行。

2. **配置 Python 环境。** 安装 Anaconda 或 Python，创建虚拟环境，再安装 PyTorch、Ultralytics、OpenCV 等依赖。

3. **处理 CUDA 与依赖问题。** 确认显卡驱动、CUDA 和 PyTorch 是否兼容。运气不好就会发现 PyTorch 根本没识别到 GPU。

4. **下载模型权重。** 找到 YOLOv8 对应的预训练权重，研究如何调用模型，以及输入图片和输出结果的数据格式。

5. **编写推理程序。** 使用 OpenCV 读取摄像头画面，将图像传入模型，再把预测结果绘制到画面上。

6. **反复调试。** 比如依赖冲突、模型文件路径错误、摄像头打不开，甚至 CUDA Out of Memory。

7. **搜索报错并重新配置。** 在 CSDN、Stack Overflow 和 GitHub Issues 之间反复横跳，直到程序终于能够正常运行。


### 2. 在 Vibe Coding 时代

现在我们只需要把官方 GitHub 仓库链接和自己的需求发给 Agent：

**Prompt 示例：**

> [https://github.com/ultralytics/ultralytics](https://github.com/ultralytics/ultralytics)
>
> 阅读这个 GitHub 仓库，我希望在当前电脑上搭建一个基于 YOLOv8 的实时目标检测项目。
>
> 请先检查我的 Python、PyTorch、CUDA 和摄像头环境，再参考官方文档安装相关依赖、下载预训练权重，并编写一个使用 OpenCV 读取摄像头、实时显示检测框的程序。
>
> 遇到报错请自行分析并修复，使用独立的 Python 虚拟环境，不要影响其他项目。
>
> 最后运行必要的测试，并告诉我如何替换模型权重，以及如何进一步使用自己的数据集训练模型。

在具备必要执行权限的情况下，Agent 可以完成：

**阅读项目 → 检查环境 → 安装依赖 → 编写代码 → 测试运行 → 排查报错。**

如果我们后面希望检测特定的机械零件，还可以继续告诉 Agent：

「现在我希望识别螺丝、螺母和扳手，请帮我设计数据集标注格式，并搭建 YOLOv8 的训练和验证流程。」

这样，我们就从简单地运行一个开源项目，过渡到了基于项目进行二次开发。

当然，Agent 能把程序跑起来，但还会存在一些潜在的问题，比如模型的识别精度、训练数据质量、误检漏检、推理延迟等指标不一定满足要求，这些内容仍然需要我们自己把关。

## 实例四：MuJoCo——从零搭建一个机器人仿真环境

如果我们希望进行机器人运动控制、机械臂操作，或者强化学习相关的实验，就可能接触到 MuJoCo 这样的物理仿真器。

假设我们今天希望 **搭建一个简单的双关节机械臂，在 MuJoCo 中实现运动控制，并可视化末端轨迹**。

这里有一个仓库：[https://github.com/google-deepmind/mujoco](https://github.com/google-deepmind/mujoco)

### 1. 在 Vibe Coding 时代之前

1. **了解 MuJoCo。** 打开官方文档、GitHub 和各种技术博客，研究 MuJoCo 的安装方式、Python 接口，以及仿真器的基本工作原理。

2. **搭建运行环境。** 安装 Python、MuJoCo 及相关依赖，尝试运行官方示例，解决可能出现的图形显示、依赖或环境问题。

3. **学习 MJCF。** 阅读 MuJoCo 的 XML 模型格式，了解 Body、Joint、Geom、Actuator 等元素分别是什么意思。

4. **编写机器人模型。** 定义机械臂的连杆几何、质量、惯量、关节位置、运动范围，以及电机执行器。

5. **编写控制程序。** 使用 Python 调用 MuJoCo 接口，实现关节位置控制，例如利用 PD 控制器驱动机械臂运动。

6. **调试物理模型。** 可能遇到机械臂突然飞走、关节方向错误、控制器振荡、模型抖动，或者末端轨迹与预期不符。

7. **补充实验功能。** 编写末端运动学计算、轨迹记录和 Matplotlib 绘图程序，再检查仿真结果。


实际上，在真正开始研究机器人控制算法之前，我们就可能花费大量时间在模型配置和仿真环境搭建上。

### 2. 在 Vibe Coding 时代

现在我们可以把 MuJoCo 的官方仓库直接交给 Agent：

**Prompt 示例：**

> [https://github.com/google-deepmind/mujoco](https://github.com/google-deepmind/mujoco)
>
> 请参考 MuJoCo 官方文档，在当前电脑上搭建一个简单的二自由度机械臂仿真项目。
>
> 使用 MJCF 定义机械臂的连杆、关节、质量、惯量和执行器，并使用 Python 编写一个基本的关节 PD 控制器。
>
> 我希望能够在仿真窗口中观察机械臂运动，指定关节目标角度，并记录和绘制末端执行器的运动轨迹。
>
> 请自行组织工程文件，安装所需依赖，运行仿真测试，并检查关节限制、控制稳定性和模型参数是否合理。
>
> 最后解释模型文件、控制器和仿真主程序分别负责什么。

Agent 可以从零生成 MJCF 模型、Python 控制代码和绘图程序，也可以在观察到异常日志或测试结果后修改控制参数和模型配置。

如果之后我们还想尝试轨迹规划、逆运动学，甚至强化学习，也可以在已有工程上继续提出需求。

但仿真运行成功，仍然可能存在一些问题。例如连杆惯量、关节摩擦、接触参数等设置不合理时，机械臂可能依旧可以正常运动，但实验结果并不具有很好的可信度。

因此，我们仍然需要理解基本的机械结构、运动学和动力学知识，才能判断 Agent 创建的机器人模型是否合理。

大家大可以通过这四个实例尝试，并通过结尾附录的文档，结合Agent去学习相关基础知识，理解Agent在这个过程中对环境和硬件进行了哪些配置和修改，建立对操作系统，软硬件的的一些基本的显性认知。

这里推荐一些比较经典的官方文档和学习资料，大家可以根据自己的兴趣选择阅读。你完全不需要盯着文字看，更多是让AI给你概括，对于你个人情况需要的内容，文档是教参，AI是老师。

看不懂，没耐心看也不要紧，建议在开发过程中，哪里遇到问题了再去查阅哪里。

## 三、如何 Vibe Coding？

终于进入正题。我们其实无法指导大家如何 Vibe Coding，但一些经验性的东西可以在这里传递：


### 4.1 至少看得懂一点代码

<div class="article-box" markdown="1">

Vibe Coding 不需要你是计算机大神，但最好也别对编程一窍不通。。Vibe Coding 降低的是代码编写基础的门槛，但无法降低软件工程的复杂度。

对于初学者来说，刚开始学习阶段建议还是多看一看Ai出的代码，也一定要保留人类对需求、架构、正确性和最终结果的控制权。

你不需要手搓什么高深算法，但如果要借助 AI生成代码做项目，那么 Python 的变量、循环、函数、类这些基本东西最好认识，Linux 命令行和 Git 也请一定了解一下。

至少 AI 改炸了项目，你得知道去哪里找问题，而不是只能再问另一个 AI。

</div>

### 4.2 最重要的是抽象能力

<div class="article-box" markdown="1">

比起自己写代码，更重要的是能把一个模糊的想法拆解成清晰的需求。

比如「帮我做个目标识别系统」就很抽象；

换成「读取摄像头画面，用 YOLO 检测行人，在视频中绘制检测框并显示置信度」，AI 就容易理解多了。

**你可以不会写具体实现，但至少应该知道输入是什么、输出是什么、整个程序大致怎么工作。**

学习AI相关知识，本人的方法是开一个Markdown手敲必要的抽象层理解，而不是什么都AI生成。

推荐使用Obisdian等**Markdown**编辑器或者插件，MD是比Word伟大一百倍的格式，又快又好看。

</div>

### 4.3 对专业问题要有基本理解

<div class="article-box" markdown="1">
AI 可以代替大量代码编写劳动，但不能替代开发者对问题本身的理解与判断。

如果只是写个网页、爬个数据，问题倒不大；如果要用 AI 做算法或者科研，最好先理解基本原理。

否则 AI 写出来一套能跑的代码，你甚至不知道它到底实现了什么，更别说判断结果对不对了。

</div>

### 4.4 必须学会使用 Coding Agent

<div class="article-box" markdown="1">

建议从 Codex、Claude Code、DSH 这类工具开始，而不是永远停留在网页聊天框里让 AI 输出代码，然后自己复制粘贴。

真正的 Coding Agent 可以直接阅读文件、修改项目、运行程序、检查报错并继续修复。

不过工具权限也要看清楚，涉及删除文件、执行陌生命令等操作时别无脑放行哦，不然会爆炸。

</div>

### 4.5 别让 AI 一上来就乱写

<div class="article-box" markdown="1">

对于已有项目，可以先让 Agent 阅读代码并介绍项目结构。

任务比较复杂时，让它先给出计划，确认方案没问题再执行。

简单任务没必要搞这么多流程，复杂任务则最好拆成几个可以验证的小步骤。

</div>

### 4.6 一定要学会测试和 Git

<div class="article-box" markdown="1">

AI 说「任务完成」不代表程序就真的没问题了，自己至少运行一下看看效果。

建议使用 Git 记录代码版本，这样能够保持对代码库的追踪、记录，至少在 Agent 把项目改炸以后，你还有机会恢复现场。

</div>

### 4.7 Prompt 没必要写成八股文

<div class="article-box" markdown="1">

网上那些要求 AI 扮演「拥有二十年经验的世界顶级架构师」的神秘 Prompt，没必要过度迷信。

对于现代 Coding Agent 还有我们初学者，思政题的解法或许是一个不错的选择——**是什么，为什么，怎么做：** 我为什么要做这个项目，项目背景和我的想法是什么，具体有哪些要求，我还有哪些地方不清楚（这个很重要）

</div>

## 附录 A：高阶知识

这里按使用场景整理一些常见术语。遇到哪个查哪个，也可以带着项目里的具体问题继续问 AI。

### 1. 输入、输出与上下文

<div class="article-box" markdown="1">

- **Prompt（提示词）**：交给模型的任务说明，也可以包含背景资料、示例和输出要求。
- **Token**：模型处理文本时使用的基本单位。一个 Token 可能对应一个字、一个词的一部分或一个标点，具体划分取决于模型使用的分词方式。
- **Context Window（上下文窗口）**：模型单次调用能够容纳的 Token 范围。对话记录、文件内容和工具返回结果都可能占用上下文，长任务需要选择和整理相关信息。
- **Hallucination（幻觉）**：模型生成了看起来可信、实际缺少依据或与事实不符的内容。写报告时遇到的虚构文献、错误实验数据，都属于需要核查的情况。
</div>

### 2. Agent 如何调用工具和资料

<div class="article-box" markdown="1">

- **Tool Calling（工具调用）**：模型提出调用某个工具的请求，由运行环境执行，再把结果返回给模型。例如读取文件、运行程序或搜索资料。
- **Harness（运行框架）**：围绕模型组织任务执行的系统，负责连接工具、管理上下文、处理权限和运行状态等工作。使用同一个模型，工具和执行方式不同，实际体验也可能有差别。
- **MCP（Model Context Protocol）**：连接 AI 应用与外部工具、数据的通用协议。工具能否被调用，还取决于具体应用的配置和授权。
- **RAG（检索增强生成）**：先从文档或知识库中检索相关材料，再交给模型参考并生成回答。比如先查课程资料，再解释其中的知识点。
- **Memory（记忆）**：把部分信息保存在当前上下文之外，在后续任务中重新读取。能记住什么、保存多久，要看具体产品的实现。

</div>

### 3. AGENTS.md：项目里的工作约定

<div class="article-box" markdown="1">

`AGENTS.md` 是写给 Coding Agent 的 Markdown 说明文件，用来记录项目背景、常用命令和修改要求。把反复需要交代的事情写进去，后续任务就有了可以共同参考的项目约定。

通常可以在项目根目录放一份通用说明，在子目录补充更具体的要求。支持这一约定的工具会按目录范围读取相应说明，较近的文件可以细化局部规则。具体加载方式仍要查看所用工具的文档。

例如，一个机器人仿真项目可以这样写：

```markdown
# 项目说明

使用 Python 编写机器人仿真，模型文件放在 models/。

## 工作约定

- 修改前先阅读 README 和现有文件。
- 只处理本次指定的部分，保留已有改动。
- 沿用项目既有的环境和依赖配置。

## 验证要求

- 运行与本次改动相关的脚本或测试。
- 交付时说明修改文件和实际验证结果。
```

建议写清楚可执行的要求，例如“使用哪个环境运行”“哪些文件需要保留”“怎样判断任务完成”，并随项目变化更新。

这些文字用于表达工作约定，实际的文件访问和命令执行仍由工具权限、操作系统和沙箱控制。

格式与更多示例可见 [AGENTS.md 官方说明](https://agents.md/)。

</div>

### 4. 模型怎样学习和使用知识

<div class="article-box" markdown="1">

- **Neural Network（神经网络）**：由多层计算和可学习参数组成的模型，可以通过训练学习输入与输出之间的关系。
- **Transformer 与 Attention（注意力机制）**：Transformer 是常见的模型架构，注意力机制帮助模型结合输入中不同位置的信息。许多大语言模型采用这类架构。
- **Training / Inference（训练 / 推理）**：训练通过数据和优化过程调整模型参数；推理使用训练好的模型处理新输入，参数通常保持不变。日常提问和让模型生成代码，主要发生在推理阶段。
- **Fine-tuning（微调）**：在已有模型的基础上继续训练，使其更适应某类任务或数据。普通对话中补充背景、举例，通常属于提供上下文。
- **RL（强化学习）**：通过与环境交互和奖励反馈学习策略。在机器人控制中，可以用它学习怎样选择动作；在语言模型训练中，也可以用奖励信号改进行为。

</div>

### 5. 运行 AI 常见的硬件与软件

<div class="article-box" markdown="1">

- **GPU**：适合执行大量并行计算的处理器，常用于模型训练和推理。显存容量会影响能够装载的模型和处理的数据量。
- **CUDA**：NVIDIA 提供的并行计算平台和编程工具。使用 NVIDIA 显卡运行深度学习程序时，经常会涉及相关运行库和版本兼容问题。
- **PyTorch**：常用的深度学习框架，提供张量计算、自动求导和模型训练等功能。运行视觉模型时，常需要安装适合当前硬件的版本。
- **Quantization（量化）**：用较低的数值精度表示模型中的部分参数或计算结果，以减少资源占用。具体能节省多少资源、是否影响效果，需要结合实现和任务验证。

</div>

### 6. 从视觉识别到机器人动作

<div class="article-box" markdown="1">

- **CV（计算机视觉）**：研究怎样从图像、视频等数据中提取和理解信息。本文的 YOLOv8 实例属于这一类应用。
- **Object Detection / Segmentation（目标检测 / 图像分割）**：目标检测通常给出物体类别和位置框；图像分割进一步区分像素所属的对象或区域。
- **Multimodal AI（多模态 AI）与 VLM（视觉语言模型）**：多模态模型处理文字、图像、音频等多种形式的信息；VLM 主要连接视觉与语言，例如根据图片回答问题。
- **VLA（视觉语言动作模型）**：结合视觉、语言等输入生成动作输出的模型，常用于机器人任务。
- **World Model（世界模型）**：学习环境怎样变化的模型，可以用于预测动作带来的后果，支持规划或控制。
- **Sim2Real（仿真到现实）**：把在仿真中训练或验证的方法应用到真实环境。仿真与真实硬件存在差异，迁移时需要继续验证。

</div>

进一步查阅：[Google 机器学习术语表](https://developers.google.com/machine-learning/glossary)、[Hugging Face 大语言模型课程](https://huggingface.co/learn/llm-course/en/chapter1/1)、[Anthropic 的 Agent 实现说明](https://www.anthropic.com/research/building-effective-agents)。

**建议重点了解：** XML、MJCF、Python API、刚体动力学、关节约束、执行器，以及仿真步长和控制频率。
